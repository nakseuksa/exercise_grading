# 题库难度自动打分算法

根据四个维度的锚点分（Rubric 整数分），自动计算题目的最终难度：**底层连续总分（Elo 式 800～2800）+ 表层非等距离散等级（L1～L5-3）**。

实现见 [`difficulty_scorer.py`](./difficulty_scorer.py)，零依赖，单个纯函数即可调用。

---

## 1. 为什么不用"直接打 1～5 分"

| 问题根源 | 本算法的对策 |
| --- | --- |
| 题目真实难度呈**右偏长尾分布**，均匀分档在低端制造噪音、在高端区分不开 | 非等距分档：低端带宽宽（400 分），高端带宽窄（150 分），顶部开放 |
| 人对难度的感知是**对数型**（韦伯-费希纳定律） | 思维深度 C 采用 **2^C 指数加权** |
| 难度是**多维向量**，单标量凭感觉打分导致标准漂移 | 拆解为 4 个正交维度分别打锚点分，再非线性合成 |
| "计算繁琐的简单题"与"思维极深的超难题"在线性求和下同分 | 指数权重 + **硬性封顶/保底规则**（见 §4） |

---

## 2. 输入：四维锚点分

| 维度 | 含义 | 取值 | 1 分 | 满分 |
| --- | --- | --- | --- | --- |
| **C** | 概念与思维深度 | 1～4 整数 | 直接识记/公式套用 | 非标构造（辅助线、不变量、反证/极端化） |
| **S** | 推理链路长度 | 1～3 整数 | 1～2 步直接推导 | 5 步以上长链路或多分支讨论 |
| **T** | 信息隐蔽度与陷阱 | 1～3 整数 | 条件显式无干扰 | 强迷惑性陷阱/关键条件极隐蔽 |
| **L** | 运算与审题负荷 | 1～3 整数 | 口算级、题干短 | 高强度计算/复杂符号/长篇材料 |

> 输入必须是整数锚点分，非整数或超范围会抛出异常——防止 LLM 打标输出 `2.5` 这类漂移值静默混入数据。

---

## 3. 算法流程

```
四维整数分 ──► ① 非线性合成 raw ──► ② 线性映射为连续分 ──► ③ 硬性规则(封顶/保底) ──► ④ 非等距分档映射 ──► DifficultyRating
```

### ① 非线性合成（思维深度指数加权）

```
raw = 2**C + ALPHA * (S + T + L)        # ALPHA = 1.5
```

- `2^C` 使 C=4 的贡献（16）是 C=1（2）的 **8 倍**；
- C=4 的最小合成值（20.5）**天然高于** C=1 的最大合成值（15.5）——"一票升档"由公式结构自动保证；
- 辅助维度线性叠加，让"纯繁琐题"能升到 L4-A，但永远够不到 L5。

### ② 线性映射为 Elo 式连续分

```
score = 800 + GAIN * (raw - 6.5)         # GAIN = 2000 / 23 ≈ 86.96
```

最易题（C=1, S=T=L=1）= 800 分，最难题（C=4, S=T=L=3）= 2800 分。

### ③ 硬性规则（防失真保险丝）

| 规则 | 效果 |
| --- | --- |
| `C = 4` | 保底 ≥ 1950，必然进入 L5-1 及以上（非标构造一票升档） |
| `C = 3` | 封顶 1949.5，最高 L4-B（压轴必须含非标构造） |
| `C ≤ 2` | 封顶 1949.5，最高 L4-A（纯繁琐题进不了压轴区） |

### ④ 非等距分档映射（左粗右细）

| 连续分区间 | 等级 | 星级 | 标签 | 带宽 |
| --- | --- | --- | --- | --- |
| 800～1200 | L1 | ★☆☆☆☆ | 基础直达 | 400（极宽） |
| 1200～1500 | L2 | ★★☆☆☆ | 常规巩固 | 300（宽） |
| 1500～1750 | L3 | ★★★☆☆ | 综合中档 | 250（中） |
| 1750～1950 | **L4-A（繁）/ L4-B（巧）** | ★★★★☆ | 进阶拔高 | 200（窄） |
| 1950～2100 | L5-1 | ★★★★★ | 压轴挑战 | 150（极窄） |
| 2100～2400 | L5-2 | 👑 S | 竞赛/超难 | 300 |
| ≥ 2400 | L5-3 | 🏛 殿堂 | 殿堂/极限 | 开放上限 |

**L4 横向拆分规则**：`T > L`（陷阱/隐蔽度高于运算负荷）→ **L4-B（巧）**，否则 **L4-A（繁）**。用于精准定位学员是"过程繁琐"还是"思维卡点"。

## 4. 使用方法

```python
from difficulty_scorer import score_difficulty

r = score_difficulty(c=4, s=2, t=1, l=1)   # 思维极深、题干短、计算少
print(r.score)   # 2147.8   —— 连续总分（存库用）
print(r.level)   # 'L5-2'   —— 离散等级
print(r.stars)   # '👑 S'   —— 前端星级
print(r.label)   # '竞赛/超难'
print(r.raw)     # 22.0     —— 合成前原始分（审计/调试用）
```

返回值为不可变的 `DifficultyRating` dataclass：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `score` | float | 连续总分（800～2800），建议存库字段 |
| `level` | str | 离散等级编码，如 `L3` / `L4-B` / `L5-2` |
| `stars` | str | 前端星级展示 |
| `label` | str | 中文标签 |
| `raw` | float | 非线性合成原始分，审计打分过程用 |

### 典型用例输出

```
C S T L     总分   等级    星级        说明
1 1 1 1    800.0   L1    ★☆☆☆☆     最简单：单知识点直接套用
1 2 2 3   1321.7   L2    ★★☆☆☆     思维简单但繁琐的题
4 2 1 1   2147.8   L5-2  👑 S       思维极深但题干短计算少
2 3 3 3   1756.5   L4-A  ★★★★☆     纯繁琐题（封顶 L4-A）
3 3 3 3   1949.5   L4-A  ★★★★☆     C=3 全满（封顶，不进 L5）
4 1 1 1   2017.4   L5-1  ★★★★★     非标构造但其余极简（保底 L5-1）
4 3 3 3   2800.0   L5-3  🏛 殿堂     最难题（顶格）
```

**两大经典反例的区分效果**：`1,2,2,3`（思维简单但繁琐）与 `4,2,1,1`（思维极深）在线性求和下同为 8 分，本算法拉开 **826 分 / 4 个等级**。

## 5. 可调参数

所有参数集中在文件顶部，调整无需改动主流程，也**不需要重新洗历史数据**（存库的是四维分 + 连续分）：

| 参数 | 默认值 | 作用 | 调整场景 |
| --- | --- | --- | --- |
| `ALPHA` | 1.5 | 辅助维度 (S+T+L) 缩放系数 | 觉得繁琐题被高估/低估时 |
| `SCORE_MIN` / `SCORE_MAX` | 800 / 2800 | 连续分上下界 | 与外部 Elo 体系对齐时 |
| `L5_FLOOR` | 1950.0 | C=4 保底分 | 调整压轴区起点 |
| `L4_CEILING` | 1949.5 | C≤3 封顶分 | 若口径为"纯繁琐题最高中档"，改 1749.5 |
| `LEVELS` | 见 §3④ | 分档阈值表 | 增删档位、调带宽 |
| `L4_A/B` 拆分规则 | `T > L` | L4 横向归类 | 如需把 S 计入"繁"侧 |

### 三个默认决策（如与教研口径不符请调整）

1. **C≤2 封顶在 L4-A 而非 L3**：依据是 L4-A"思路常规但负荷大"的定义正好对应低 C 高 S/L 的题。
2. **L4-A/B 仅比较 T 与 L**，未把推理长度 S 计入"繁琐"侧。
3. **L5-3（殿堂）阈值沿用 2400**，实测 C=4 且辅助维度中上（如 4,2,2,2 = 2408.7）即进殿堂，偏宽松；若希望殿堂更稀有，可调至 2500～2600。

## 6. 校验规则与错误处理

```python
score_difficulty(2, 5, 1, 1)   # ValueError: 维度 s 超出范围 [1, 3]
score_difficulty(1, 2.5, 1, 1) # ValueError: 维度 s 需为整数锚点分
score_difficulty("1", 1, 1, 1) # TypeError:  维度 c 需为数字
```

## 7. 与动态校准（Elo）的衔接

本算法输出的连续分可直接作为**冷启动先验** $D_{\text{prior}}$。运营期积累真实做题数据后，可按 Elo 对局规则动态更新（题目视为"参赛选手"）：

$$D_{\text{new}} = D_{\text{old}} + K \cdot (\text{Expected\_Pass} - \text{Actual\_Pass}), \quad \text{Expected\_Pass} = \frac{1}{1 + 10^{(R_{\text{student}} - D_{\text{old}})/400}}$$

注意切勿用整体错误率直接代替难度（超难题只有高水平学生去做，存在**幸存者偏差**）。前端展示层始终通过 §3④ 的非等距阈值表从连续分映射等级，动态校准只需更新分数，无需触碰分档逻辑。

## 8. 存储建议

数据库建议存 **4 个维度的整数分 + 1 个连续总分**：

```
c_score INT, s_score INT, t_score INT, l_score INT, elo_score FLOAT
```

前端按业务场景用非等距阈值映射为等级/星级展示。这样后续无论如何调整分档颗粒度或权重参数，都不需要重新洗数据。
